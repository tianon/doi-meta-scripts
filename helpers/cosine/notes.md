each build server has access to a "trust boundary specific" ("staging") key (AWS KMS or generated by hand locally); for example, all of our AWS workers would likely share a single "staging" KMS key, but each of risc and mips has a separate hand-generated key

we will also have a single "production" key that is the one we use to sign builds that actually end up in "arch/foo" and "library/foo" on Docker Hub (likely in AWS KMS, but that doesn't actually matter much either way)

when a build is performed, the appropriate "staging" key is used to sign the image manifest, and that signature object is included in the image index pushed to the staging repository
